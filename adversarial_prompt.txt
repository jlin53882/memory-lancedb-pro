## 一、上游最新 Pipeline（hybridRetrieval）精確順序

```
1.  embedQuery() + buildBM25Query()
2.  Promise.all([runVectorSearch(), runBM25Search()])   ← 兩階段平行搜尋
3.  fuseResults()                                       ← RRF fusion
4.  filter: score >= minScore
5.  filter: !isMemoryExpired()                         ← #8111e26 移至此（scoring 之前）
6.  rerankResults()                                      ← 若 rerank !== "none"
7.  applyRecencyBoost()
8.  applyImportanceWeight()
9.  applyLengthNormalization()
10. filter: score >= hardMinScore
11. applyDecayBoost() 或 applyTimeDecay()
12. filterNoise()
13. applyMMRDiversity()                                 ← MMR 多樣性去重
14. slice(0, limit)
15. return
```

`vectorOnlyRetrieval()` 與 `bm25OnlyRetrieval()` 架構類似，**亦有獨立的 expiry_filter**，位於搜尋之後、scoring 之前。

## 二、🔴 高風險衝突（需要 maintainer 確認才能實作）

### 衝突 A：MMR 衝突 — AliceLJY 的建議本身有矛盾（Q5）

| 項目 | 內容 |
|------|------|
| **提出者** | jlin53882（Issue #538 Q5）|
| **緊急度** | 🔴 阻塞 |
| **狀態** | ❌ **從未得到回覆** |

**問題**：

AliceLJY 在 Issue #538 Q2 回答中說「在 MMR 之後插入」B-2，理由是「MMR 負責多樣性，neighbor enrichment 是對 top-K 結果的補充」。

但 MMR 的工作就是「刪除相似的 items」。如果某個 neighbor 與 MMR 已選中的 result 相似，MMR 已經把它刪掉了。**B-2 在 MMR 之後執行時，已被 MMR 刪除的相似 items 永遠無法成為 neighbors**。

**對抗式 review 發現**：這個衝突的根源在於「B-2 的 neighbor lookup 是對什麼做查詢」沒有被定義清楚：
- 如果 B-2 是對每個 MMR survivor 的 text 做獨立的 `bm25Search()` 資料庫查詢，則 MMR 完全不影響 neighbors 的數量
- 如果 B-2 是對 MMR 的整個輸出集合再做一次 BM25 search，則 MMR survivors 決定了候選範圍

**三個可選方案**：

| 方案 | 做法 | 風險 |
|------|------|------|
| A | 將 B-2 插入點改為 MMR **之前**（步驟 12 之後）| 改變了 AliceLJY 的明確指示，需要 maintainer 確認 |
| B | 維持 MMR 之後，接受「neighbors 僅限 MMR survivors」的代價 | 可能在 PR review 時被 challenge |
| C | 如果 B-2 的 neighbor lookup 是對每個 recall result 獨立的資料庫查詢，則 MMR 完全不影響 | 需要在 PR 中明確定義 neighbor lookup 的輸入 |

| 項目 | 內容 |

| **狀態** | 上游已合併的變更 |

**問題**：

如果 B-2 在 MMR 之後插入，且 neighbor lookup 使用 MMR 輸出作為輸入，expired entries 不會出現在 MMR 輸出中。

**對抗式 review 發現**：這裡有一個關鍵誤解——如果 B-2 的 neighbor lookup 是對每個 recall result 做**獨立的資料庫查詢**，則：
- MMR 不影響 B-2 的 neighbor lookup 範圍

- 如果 B-2 的 `bm25Search()` 本身不过滤 expired entries（需要確認 store.bm25Search 是否有 `excludeInactive` 選項），則 expired neighbors 會被加入輸出

**建議**：
在 B-2 的 neighbor lookup 階段確認 store.bm25Search() 是否有 `excludeInactive` 選項。如果沒有，需要在查詢結果中自己過濾。
