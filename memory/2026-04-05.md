## PR #466 — autoRecallTimeoutMs parsePluginConfig Fix（2026-04-05 晚間）

### 背景
- PR466 修復：`parsePluginConfig` 缺少 `autoRecallTimeoutMs` 解析，導致 validator 以 `additionalProperties: false` 拒絕使用者設定
- 預設值討論後定為 5000ms（原為 3000ms）

### Review by rwmjhb（Must Fix）

| 問題 | 說明 |
|------|------|
| Duplicate key in configSchema | `autoRecallTimeoutMs` 出現兩次，後者覆蓋前者 |
| 預設值不一致 | `parsePluginConfig` 用 `?? 3000`，runtime consumer 用 `?? 5000` |

### 處理過程

**根本原因**：rebase conflict resolution 多次出錯：
1. conflict marker 吃掉 key 名稱（`"autoRecallTimeoutMs": {` 消失）
2. 導致巢狀 value 變成無 key 的孤兒 entry
3. `edit` tool 對大 JSON 的 replace 不精確，來回修了多次

**修復策略（最終有效）**：
- 放棄複雜 rebase，用 `git rebase --skip` 跳過所有衝突的 schema commits（因 upstream/master 已含正確 schema）
- 只重新 apply `index.ts` 的 `parsePluginConfig` 修正（真正新的程式邏輯）
- 用 Python 讀取驗證 JSON 結構，避免 PowerShell `Select-String` 誤報

**最終正確狀態（d926298）**：
- `configSchema.properties.autoRecallTimeoutMs`: `maximum: 60000, default: 5000`
- `parsePluginConfig`: `?? 5000`
- Runtime consumer: `?? 5_000`
- `uiHints.autoRecallTimeoutMs`: `label + help + advanced` 完整

### Key Lessons（寫入 .learnings/LEARNINGS.md）

1. **Rebase conflict marker = 合併雙方**：不是二選一，是同時保留
2. **gh comment 中文 → `--body-file`**：PowerShell 直送中文 body 會有 cp950 編碼控制字元問題
3. **PR head branch 名稱 ≠ local branch 名稱**：James 說「PR466」，但 head branch 是 `fix/autoRecallTimeoutMs-parse`，需先 `gh api --jq '.head.ref'` 確認
4. **複雜 JSON 衝突 → Python script**：比 `edit` tool 的字串比對精確太多
5. **Select-String 長字串誤報**：PowerShell `Select-String "autoRecallTimeoutMs"` 會匹配任何包含該字串的「長行」，即使行號數字也在結果中（行 14903 的 `timeoutMs` 也被匹配）
6. **upstream/master 可能已含相同功能**：schema commits 全被 skip，rebase 策略需先確認 upstream 是否已有相同 entry
