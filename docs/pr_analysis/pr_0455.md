## PR 描述

## Proposal A Phase 1  Recall Boost

**Issue**: #445

### What
Dynamic importance feedback —Phase 1 (recall boost).

When a recalled memory is actually used in the agent's response, boost its importance to reinforce high-value memories.

### Signal
- **Trigger**: Auto-recall hook injects memories → agent uses some in response
- **Adjustment**: `importance += importanceBoostPerUse` (default +0.05, cap 1.0)

### Mechanism
1. Auto-recall hook now stores recalled memory IDs in `ctx.__recalledMemoryIds`
2. Phase 1 hook (`agent_end`, priority 50) reads recalled IDs
3. Checks if memory text appears in response (heuristic: first 20 chars of memory text found in response)
4. If used → boost importance by `importanceBoostPerUse`

### Config
```
feedbackSignal.importanceBoostPerUse: 0.05 (default)
```

### Files Changed
- `index.ts`: PluginConfig interface + auto-recall __recalledMemoryIds storage + Phase 1 hook

### 這是什麼樣的改動？

**PR 目的**：
這是 Proposal A（反饋信號機制）的第一階段實作，名為「Recall Boost」。目標是當 agent 實際使用到被召回（recall）的記憶時，自動提升該記憶的 `importance` 分數，藉此強化高價值記憶、讓它們在未來檢索時排名更前面。

### 運作流程

1. **觸發時機**：`agent_end` hook（優先權 50）
2. **讀取資料**：從 `ctx.__recalledMemoryIds` 取回本次被召回的記憶 ID 清單
3. **使用判斷**：用啟發式方法（記憶文字前 20 字元是否出現在回應中）檢查記憶是否被使用
4. **重要性 Boost**：若被使用，`importance += 0.05`（預設值，可設定），上限 1.0
