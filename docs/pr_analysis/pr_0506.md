## 維護者回覆 / Review

### Issue Comment #1 (chatgpt-codex-connector[bot]) - 2026-04-04
- **P2 Badge**：Remove `id-` pattern from usage-marker detection
- **內容**：
  The usage-marker regex currently includes `id[-:]`, so any long response that merely repeats an injected ID (for example `... id-abc123 ...`) sets `hasUsageMarker=true`. That makes the `hasMatchingId && hasUsageMarker` check effectively equivalent to `hasMatchingId` for common ID formats, which contradicts the intended "ID + marker" gate and will overcount recall usage in feedback scoring paths.

### Issue Comment #2 (chatgpt-codex-connector[bot]) - 2026-04-04
- **P2 Badge**：Require usage marker before accepting summary match
- **內容**：
  The summary branch returns `true` on any verbatim summary hit of length >=10 without checking `hasUsageMarker`. This diverges from the function contract in the doc comment and from the stricter ID path, so long responses that incidentally echo injected summary text will be treated as confirmed recall usage even when no explicit recall signal is present.
