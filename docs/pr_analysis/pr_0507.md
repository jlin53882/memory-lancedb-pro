## PR 描述

Proposal A Phase 1: Dynamic Importance Feedback Signals. Implements per-recall usage tracking and importance scoring via hooks on agent lifecycle events.

### What was built

#### Hooks
- `agent_end` (priority 20): Captures agent response text into pendingRecall
- `before_prompt_build` (priority 5): Scores recall usage on next turn
- `session_end` (priority 20): Cleans up pendingRecall entries

#### isRecallUsed() AND Logic
Checks for specific memory ID presence AND generic usage markers (both required):
```typescript
const hasSpecificRecall = injectedIds.some(id => response.includes(id));
if (hasSpecificRecall) {
  for (const marker of usageMarkers) {
    if (response.includes(marker)) return true;
  }
}
```

#### Per-Recall Scoring
Each recallId scored individually — no cross-contamination between memories.

#### Key Fixes (from #493 review)
- AND logic prevents generic phrases from boosting all injected memories
- `bad_recall_count` increments correctly in error/miss paths
- `sessionKey:agentId` composite key prevents cross-agent interference
- Session_end properly cleans composite keys (no memory leak when autoCapture=false)

## 維護者回覆 / Review

### P1 Comment (chatgpt-codex-connector[bot])
**P1 - Restore autoCapture block boundary before feedback hooks**

The `if (config.autoCapture !== false)` block is no longer closed before the new feedback-hook section, so subsequent registrations (e.g., `selfImprovement` hooks starting at `if (config.selfImprovement?.enabled !== false)`) are now conditionally skipped whenever `autoCapture` is disabled. This is a behavioral regression for configs that set `autoCapture: false` but still rely on command/session hooks, and it changes feature wiring far beyond recall feedback.

### P2 Comment (chatgpt-codex-connector[bot])
**P2 - Validate feedback config field types before consumption**

`parsePluginConfig` now forwards `cfg.feedback` as an untyped object, but the scoring hook later assumes `confirmKeywords`/`errorKeywords` are arrays and calls `.some(...)` on them. If a deployment supplies these as strings (a common JSON/YAML misconfiguration), the hook throws and the `catch` path disables recall scoring for that turn, so custom feedback settings can silently break the new feature.
