## PR 描述

Proposal A Phase 3: Configurable Feedback Amplitudes. Extracts hardcoded feedback parameters into a FeedbackConfigManager class, allowing deployment-level customization.

### What was built

### FeedbackConfigManager (src/feedback-config.ts)
```typescript
class FeedbackConfigManager {
  computeImportanceDelta(event: 'use'|'confirm'|'miss'|'error', recallCount, badRecallCount): number
  isConfirmKeyword(text: string): boolean
  isErrorKeyword(text: string): boolean
  static fromRaw(raw): FeedbackConfigManager
  static defaultConfig(): FeedbackConfig
}
```

### Configurable Parameters
| Parameter | Default | Description |
|-----------|---------|-------------|
| `importanceBoostOnUse` | 0.05 | Normal usage boost |
| `importanceBoostOnConfirm` | 0.15 | Explicit confirmation boost |
| `importancePenaltyOnMiss` | 0.03 | Miss penalty |
| `importancePenaltyOnError` | 0.10 | Explicit error penalty |
| `minRecallCountForPenalty` | 2 | Recall threshold for penalty |
| `confirmKeywords` | ["是對的", "確認", "正確", "right"] | Confirmation detection |
| `errorKeywords` | ["錯誤", "不對", "wrong", "not right"] | Error detection |

### Backward Compatibility
All defaults match Phase 1 hardcoded values exactly. No breaking change for existing deployments.
